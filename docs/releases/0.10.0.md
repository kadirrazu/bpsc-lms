# Release 0.10.0 — Issue Register, Confirmations and Loan Actions

Baseline: v0.9.0.

- Issue Management dropdown immediately after Dashboard groups Issue Book, Issue Requests, Issue Register and Fine Reports.
- Issue Book opens a contextual confirmation modal before submitting. Librarian/Staff and other authorized operators can open it with a book preselected from Book Details. The existing two-book/15-day policy and Librarian limit confirmation remain intact.
- New searchable/paginated Issue Register with accession, title, author, member, issue/due/return timestamps and issued-by identity. New issues retain book/issuer snapshots. Existing snapshots/reviewer provenance are reconstructed by migration; unknown issuer is labelled Not recorded.
- Reminder sends a private member-dashboard return message, with one current reminder per active loan. Returned loans disappear from reminder results.
- Renew opens a modal for 15 or 1–365 days, extends from the later of due time/today, and preserves issue history/counts. Locked revision checks reject duplicate/stale renewal submissions.
- Fine/clear-fine flags can be confirmed, filtered and exported to a UTF-8 CSV report. All actions are authorized and audited.

See `docs/issue-register.md` for exact behavior.

## Apply

Back up project/database, extract the root-relative ZIP over v0.9.0, then run:

```bat
php artisan optimize:clear
php artisan migrate --force
php artisan test
```

Migration adds register snapshots, issuer/fine/renewal fields and the reminder table, then backfills existing records in batches. Existing issue/return dates and borrowing counts remain unchanged. No dependency install or asset rebuild is needed: a standalone, versioned same-origin script is included for the new modals. README and old migrations are unchanged.

Eight new regression tests were added; existing issuance tests now explicitly acknowledge confirmation. Suite totals 117 tests.
