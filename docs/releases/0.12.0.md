# 0.12.0 — Guided Catalog Imports

Date: 8 November 2026. Baseline: `project-refrence-lms-05-11-2026-03-52-PM-OFFICE.zip` (v0.11.2).

## Result

All four catalog imports now require Upload & Preview followed by Confirm Import. Invalid rows can be corrected through Edit Row without saving catalog records. Book row correction uses the existing searchable author/category multi-select and publisher selector. Preview displays the actual selected names and IDs and paginates 20 rows while validating the entire batch.

Book templates are generated from the current database and contain Books, Authors, Publishers, Categories and Instructions sheets. Publishers have an ID–name dropdown; Collection Method also has a dropdown. Author/category IDs are pipe-separated. Plain publisher IDs are accepted too, so the publisher dropdown guides entry while the server remains authoritative. Master templates contain blank Data and Instructions sheets. No template contains example catalog records that could be accidentally imported.

## Compatibility

**Download a fresh template.** Book relation headers changed from names to `author_ids`, `publisher_id`, `category_ids`. Old name-based templates are rejected. IDs belong to this installation. Create/import missing master records first; importing books does not create master records from arbitrary text. New records only; existing records are never overwritten. Any invalid row blocks the entire import.

## Integrity

Confirmation revalidates all rows and referenced database entries in one transaction. A preview fingerprint detects changed data or reference names; stale edits/confirmations are rejected. Draft operations are serialized by a file lock, and completed confirmations are idempotent. Private previews are bound to the uploading user/session, expire after one hour, and can be cancelled. A scheduled maintenance command and upload-time cleanup remove stale preview files. All existing import audit events remain.

Limits remain XLSX, 500 data rows, 10 MB uploaded and 30 MB expanded. Existing protections for formulas, external links, macros, duplicates, accession text/leading zeros and field validation remain. Related ID existence is checked in bulk rather than per cell. Confirmation posts only token/revision/fingerprint; it does not post hundreds of rows through PHP's input-variable limit.

## Apply

Extract the root-relative Paste & Replace ZIP over the stated baseline. Preserve the existing environment/database. Run:

```sh
php artisan optimize:clear
php artisan test
```

No migration, Composer update or frontend build is required. Private application storage must be writable. If Laravel's scheduler is not already enabled, use the existing Windows/server scheduler setup for `php artisan schedule:run` each minute. Manual cleanup is `php artisan library:prune-import-drafts`.

The stable root README, existing migrations, database files, Composer manifests/lock and built frontend assets are unchanged. Operational guidance is in `docs/imports.md`.

## Validation

Final full Laravel suite: **133 passed, 1,386 assertions, zero failures/errors**, using native PHP 8.3.6, the baseline's locked dependencies and SQLite in-memory test database. The machine-readable result is `docs/validation/0.12.0-tests.json`. No production database was used. MySQL/WAMP-specific execution and browser visual rendering were not performed here.

The 22 import/admin tests include nine new preview-flow regressions: upload without writes, exact ID relations and names, single confirmed import, correction of unknown IDs, whole-batch rejection, all three master imports, actor/kind/session/role isolation, changed-master revalidation, cancellation/expiry/stale edits, database template references/dropdown configuration and preview pagination. Existing import tests were updated for explicit confirmation and blank ID-based templates.
