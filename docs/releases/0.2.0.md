# Release 0.2.0 — 31 October 2026

Baseline: Library Management System v0.1.0 English boilerplate.

## Changes

- Product name shortened to **Library Management System**; commission and developer credits retained.
- Professional indigo/slate administrative theme and separate teal member portal. Header/footer backgrounds span the viewport; root offsets reset. Responsive user filter actions stay on one line with a gap.
- Users, Designations, Units, Roles & Permissions and Audit Logs grouped under **Administration**, filtered by role.
- Fixed roles: Administrator, Librarian, Library Staff and Library Member. Existing `borrower` accounts migrate to `library_member` with identity and passwords preserved; old sessions/tokens are revoked.
- All original Scheduler designations restored. Added Librarian, Assistant Librarian, Law Adviser, Law Officer, Member, Chairman and Personal Secretary. Existing/custom designations remain.
- Scheduler's 27 user units seeded. Administrator-only Unit CRUD; renamed units retain assignments through stable internal codes. Assigned units cannot be deleted or deactivated. Existing custom units are retained.
- Unit create/edit/delete recorded by model auditing; existing request, account, designation and authentication audit events retained. Administrator and Librarian can view logs. Passwords/tokens are excluded.
- Members sign in to their own portal and use its layout for profile/password. Catalog and My Requests currently explain service availability; live search, issue submission and issue history require the future catalog/circulation modules.
- Root README replaced with a concise stable guide; further changes documented under `docs/releases/`.

## Update an existing v0.1.0 installation

1. Back up the project and database.
2. Extract this Paste & Replace ZIP over the project root. Preserve `.env`, `vendor/`, uploaded files and the database.
3. Optionally set `APP_NAME="Library Management System"` in `.env` for mail/environment metadata. The displayed product name is updated by this release.
4. Run:

```bat
php artisan optimize:clear
php artisan migrate --force
php artisan db:seed --class=DesignationSeeder --force
php artisan db:seed --class=UnitSeeder --force
php artisan test
```

No database reset, new APP_KEY or Composer dependency change is required. Compiled assets are included; run `npm ci --ignore-scripts` and `npm run build` only when rebuilding them.

Sign in again after updating a former Borrower account. Test Administrator Unit CRUD, the Administration dropdown, member login/profile/password and user filters. New installations should use the full initial project plus this patch and follow the root README.

## Data safety

Migration keeps existing users, designations, custom unit codes and passwords. It adds matching Unit records for old user assignments. Rollback retains added designations. Only unassigned units can be removed; soft-deleted user records also count as assignments.
