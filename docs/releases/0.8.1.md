# Release 0.8.1 — Withdrawal Deployment Check and Confirmation

- Withdraw Request uses a red outline button and the existing confirmation handler. Cancel stops the submit event; OK permits the normal CSRF-protected POST.
- Withdrawal checks that its timestamp column is installed. If the migration is pending, it returns a readable validation message without changing the request, and writes an actionable warning in the server log instead of attempting an invalid update.
- The audit timestamp is serialized from the same Carbon timestamp supplied to the update, avoiding a dependency on immediately recasting the saved model attribute. Ownership, status and locking checks remain in place.

The reported generic server error did not include an exception log, so its exact cause is unconfirmed. A missing withdrawal timestamp migration is one supported failure case; this patch does not suppress unrelated exceptions.

## Apply

Extract over v0.8.0, then run all three commands:

```bat
php artisan optimize:clear
php artisan migrate --force
php artisan test
```

The v0.8.0 withdrawal migration and model are included unchanged to cover an incomplete file deployment. Existing migrations will not rerun. No npm/Composer update or asset rebuild is required. If the error continues, inspect the latest exception in `storage/logs/laravel.log` around the withdrawal request time.

## Verification

The existing JavaScript confirmation handler was executed in an isolated Node harness: Cancel prevented submission, OK allowed it. Source checks confirmed the matching form hook, compiled handler availability and schema guard. Added one missing-migration regression test; suite totals 88 tests. Native PHP remains unavailable (`php: command not found`), so no native Laravel test/migration or browser result is claimed.
