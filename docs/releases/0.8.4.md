# Release 0.8.4 — Member Filters and Active Loan Notice

Apply over v0.8.2 or v0.8.3. This cumulative patch includes the v0.8.3 management filter alignment correction.

- Member Requests has a common book search plus independent Request Status and Loan Status selectors. Search covers both lists by BN/EN title, accession/call number, author, publisher or category. Each status selector applies only to its labelled section.
- Search is always restricted to the signed-in member. All filters survive both independent 20-record paginators; Search resets pagination, Clear resets search and statuses. Invalid filter values are rejected. Archived history and literal `%`/`_` searches remain supported.
- A book's member detail page checks for an active loan belonging to the current member. If found, it shows the issue date and an issued-to-you notice instead of the request form. Another member's loan does not trigger that personal notice. Once returned, the request form is available again subject to normal stock checks. The existing server-side duplicate-loan guard remains authoritative.
- Management search/status fields are top-aligned, with buttons aligned to the inputs; search help text no longer shifts the status field downward.

Extract the root-relative ZIP over the current project, then run:

```bat
php artisan optimize:clear
php artisan test
```

No migration, Composer/npm update or asset rebuild is needed. Existing README, migrations, request/withdrawal rules and data remain unchanged.

Source/scope checks covered ownership scoping, grouped search predicates, status semantics, paginator query strings, active-loan lookup and conditional form visibility. Six regression tests were added; suite totals 98 tests. Native PHP is unavailable (`php: command not found`), so the full Laravel suite, native database and browser rendering remain unverified here. No native passing result is claimed.
