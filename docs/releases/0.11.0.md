# 0.11.0 — Borrowing Settings and Issue Register Polish

Date: 5 November 2026. Applies over v0.10.0.

- Issue Register combines accession, title and authors into one Book column with separate lines. Actions remain side by side; narrow screens can scroll the table horizontally.
- Renew and Fine are visible only after the due timestamp has passed. The same condition is enforced inside the locked server transaction. Returned loans cannot renew. Clear Fine remains available for existing flags. Overdue renewals extend from now, using the configured period by default or a chosen 1–365-day extension.
- Administrator-only Administration → Borrowing Settings configures maximum active books (default 2, range 1–100) and standard loan days (default 15, range 1–365).
- Shared request-scoped policy drives member active-plus-pending limits, direct issues, approvals, central model validation, due dates, warnings, confirmation dialogs and renewal defaults. Librarian override confirmation also binds to the policy revision. Settings edits are audited.
- Existing due dates are preserved. Lowering a limit blocks further standard issues/requests until capacity is available; it does not cancel existing loans or pending requests. Approval always rechecks current policy.
- Stable root README, existing migrations, environment, database and asset manifest are unchanged.

## Apply

Extract this root-relative Paste & Replace patch into the existing v0.10.0 project. Run:

```sh
php artisan optimize:clear
php artisan migrate --force
php artisan test
```

The new migration creates and seeds one borrowing-settings row. No frontend build or destructive reset is needed. Do not run migrate:fresh.
