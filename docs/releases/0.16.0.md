# 0.16.0 — Exceptional issues

24 November 2026. Apply over the 17 November 2026 reference project (v0.15.3).

After replacing files, run:

```bash
php artisan optimize:clear
php artisan migrate
```

Only a Librarian can enable **Allow exceptional issue** on Issue Books. Enter the reason, select books, and choose an available accession for every copy. Each title starts with one copy. **Add another copy** adds another accession selection for that title. Existing copies held by the member can also be supplemented.

The review dialog shows the member, borrowing limit, current loans, titles and copies being issued, resulting loan count, all selected accessions, and the reason. **Confirm Exceptional Issue** completes the operation. The existing form accepts up to 100 titles per operation. Exceptional issues also accept up to 100 copies per operation.

Administrator, Library Staff, and Library Member retain their normal borrowing rules. The exceptional option is restricted on the server as well as in the form. Member requests count every physical copy currently held, plus pending requests, against the configured limit. Loan duration and renewal settings apply to exceptional issues.

Every copy has a separate loan record with quantity one. Returning one copy leaves the other copies on loan and produces a separate Return Receipt. The shared Issue Receipt lists every accession, with separate title and copy totals.

Issue Register and Issue Requests identify exceptional loans and show their authorization details. The register's **Issue type** filter applies to its PDF, Excel, and CSV downloads. Reports include the reason, and spreadsheet/CSV downloads also include the configured limit and recorded loan counts. The audit log stores the operator, member, reason, accessions, time, and before/after copy counts.

No frontend build or dependency change is required.
